# 记忆：会忘的那种

## 存哪

```
~/.dsh/life-mode/memory/
  memory.jsonl      图谱正文（实体 + 关系 + 观察），官方 server-memory 写
  meta.jsonl        旁注：每条观察的强度、分层、置顶、归档原因，我们的索引服务写
  backups/          归档/合并前的备份
```

`memory.jsonl` 每行一个 JSON：实体行 `{"type":"entity","name":…,"observations":[…]}`，
关系行 `{"type":"relation","from":…,"to":…}`。

`meta.jsonl` 按 `key` 记：`key = sha256(实体 + 规范化正文)` 前 16 位。规范化的做法是
去掉全部标点和空白、`NFKC` 折叠、转小写——这样「今天下午打游戏」和「今天下午，打游戏。」
是同一个 key。

## 三层

| 层 | 什么意思 |
|---|---|
| `core` | 置顶的。永不被淡忘，召回时优先 |
| `active` | 默认。参与召回，会衰减 |
| `archive` | 归档。默认不参与召回，`includeArchive` 能翻出来 |

归档是**软删**：原文一直在 `memory.jsonl` 里，只是不在默认召回里。

## 打分

```
score = 0.60 * 相关度 + 0.25 * 重要性 + 0.15 * 强度
```

这个式子是 **Generative Agents**（Park et al., 2023）那套，不是我们发明的。

- **相关度**：查询和观察正文的词面重合（去掉标点后的 token 交集加权）
- **重要性**：正文长度、是否含疑问/决定/日期这类信号
- **强度**：时间衰减后的剩余强度，初始 1.0

低于 `minRel`（默认 0.06）的不注入。这个门槛很重要——没有门槛，任何查询都能匹配到
几条垃圾，每轮都塞进去。

## 衰减

`scripts/decay.mjs`，可以定时跑（默认不在安装时自动挂定时任务）：

| 参数 | 默认 | 意思 |
|---|---|---|
| `halfLifeDays` | 4 | 强度每 4 天减半 |
| `MIN_STRENGTH` | 0.12 | 低于这个才考虑归档 |
| `MIN_AGE_DAYS` | 14 | 太新的不归档，哪怕强度低 |
| `MAX_PER_RUN` | 40 | 一次最多归档多少条，防止一次清太多 |

三个条件必须同时满足才归档：**够旧、够弱、没被置顶**。这一步是故意的保守——
错删一条真的记忆，代价远大于多留几条废话。

跑之前先备份（脚本自己会），`--apply` 才真写。

## 日摘要

一天聊下来的流水会攒成一堆短观察（`生活·流水` 实体）。攒够一段，脚本把它们压成一条
「日摘要」写回图谱，原条归档。这就是「下午玩得比较多」的来源——不是模型每次现编的，
是从流水里压出来的。

## 每轮怎么用

```
用户这句话
   ↓
拿它当查询，从 active+core 里打分召回
   ↓
过 minRel 门槛、过去重（同一观察 5 分钟内不重复注入）
   ↓
挑 k 条（默认 2），每条压到 maxFrameChars 字（默认 60）
   ↓
和 persona/life-style.md 拼成一段
   ↓
总字数压到 maxChars（默认 260）
   ↓
作为一条 system-reminder 插在本轮用户消息后面
```

**注入的不是记忆原文，是摘要帧。** 原文想看得用 `memory_recall` 去捞。这样每轮的固定
开销可控，跟图谱长多大无关。

## 为什么不用向量检索

词面重合 + 三因子打分，在这个规模上够用，而且**零依赖、可解释、可调**。
换成向量检索要引一个 embedding 模型或服务，安装成本、隐私、失败模式全都上去了。

真到了几万条、词面匹配明显不够的时候再换。现在没到。
